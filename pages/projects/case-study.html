Project Overview

This case study documents my semester-long journey designing ModuMuse, a plugin-based audio library management application that empowers audio enthusiasts to fully customize their music experience. The project emerged from recognizing a gap in the market: while streaming services dominate music consumption, many enthusiasts still maintain local audio libraries but lack comprehensive tools to manage them effectively.

Throughout this project, I employed a user-centered design approach, moving through the full UX lifecycle from initial research through evaluation of high-fidelity prototypes. This case study showcases my process, methods, and the evolution of ModuMuse from concept to a refined design ready for development.

Research: Understanding User Needs

Fragmentation

Users often need multiple tools to accomplish their audio management goals - one for playback, another for organization, and yet another for format conversion.

Customization Limitations

Existing solutions rarely allow users to tailor the software to their unique workflows.

Metadata Management

Maintaining consistent metadata across large collections is time-consuming and error-prone.

Defining User Needs

Based on my research, I formulated three core user need statements:

  1. Power users and audio enthusiasts need a way to customize and extend their music management software because existing solutions often lack specific features they desire.
  2. Music collectors need an efficient way to maintain consistent metadata across their library because managing large collections manually is time-consuming and error-prone.
  3. Audio enthusiasts need flexible format conversion and quality management tools because they work with content from various sources and need to optimize for both quality and storage.

Design Vision

I will design a plugin-based audio library management application to help audio enthusiasts and collectors achieve complete control over their music collections by allowing them to customize and extend every aspect of their library management workflow through an open ecosystem of interoperable tools and plugins.

Design: Exploring Possibilities

Ideation and Concept Development

With my vision established, I began exploring potential design directions. I focused on creating a flexible, modular interface that could adapt to different user needs while maintaining a cohesive experience.

I generated multiple design concepts that approached the core functionality from different perspectives:

  1. Spotify/YouTube Music-inspired interface (Design A): Featuring larger visual elements, a persistent bottom navigation bar with icon labels, and a grid-based song browsing view.
  2. VLC-style interface (Design B): Utilizing a more compact layout with a hamburger menu, list-based song browsing, and higher information density.

Both designs incorporated the core modularity concept but with different interaction patterns and visual styles.

Information Architecture

I developed a comprehensive information architecture for ModuMuse that organized functionality into clear categories while supporting the plugin-based nature of the application. Key considerations included:

  • Creating logical groupings for core functionality (Library, Playback, Plugins, Settings)
  • Designing a flexible navigation system that could accommodate user-added plugins
  • Establishing clear pathways for discovering, installing, and managing plugins

Design Evolution

The initial design concepts evolved significantly based on peer feedback and further ideation. I explored different approaches to key challenges like:

  • Plugin Discovery: How to make the plugin ecosystem browsable and understandable
  • Customization Controls: How to provide powerful customization without overwhelming users
  • Metadata Management: How to streamline the process of organizing large music collections

Throughout this process, I maintained a focus on balancing power and simplicity—creating an interface that would be approachable for casual users while providing the depth and flexibility demanded by power users.

Prototyping: Bringing Ideas to Life

Low-Fidelity Explorations

I began the prototyping phase with low-fidelity wireframes to explore navigation flows and screen layouts. These wireframes focused on establishing the core information architecture and interaction patterns without getting distracted by visual design details.

A/B Testing Prototypes

As my design concepts matured, I created two distinct high-fidelity prototypes in Figma for A/B testing:

  • Prototype A: Featured a Spotify/YouTube Music-inspired design with larger visual elements, a persistent bottom navigation bar, and a grid-based song browsing view.
  • Prototype B: Utilized a more compact VLC-style interface with a hamburger menu, list-based song browsing, and more content visible on a single screen.

Both prototypes included:

  • Home screens with music discovery options
  • Library browsing interfaces
  • Plugin management screens
  • Playback controls
  • Organization and tagging tools

The A/B testing approach allowed me to evaluate fundamental navigation and layout differences before committing to a single direction.

Refined Prototype

Based on the A/B testing results, I developed a refined prototype that combined the strengths of both previous versions. This prototype featured:

  • Design B's space-efficient interface as the foundation
  • A collapsible navigation bar that could toggle between expanded and compact modes
  • Improved text contrast and visual hierarchy
  • Customizable view options for music browsing (grid or list view)
  • A redesigned plugin interface with clearer configuration options

I implemented this prototype in Figma with high-fidelity visual design, realistic content examples including album artwork, and interactive elements to simulate key user flows.

In the final stages of prototyping, I also created a simple web-based prototype to demonstrate some of the core functionality to friends and gather additional feedback. This helped validate the design direction before moving to formal evaluation.

Evaluation: Testing with Users

Think-Aloud Protocol

For my evaluation strategy, I employed the think-aloud protocol to gather rich qualitative feedback on the user experience. This method allowed me to understand not just what users were doing, but why they were doing it and what they were thinking throughout the interaction.

I conducted two rounds of testing:

  1. Initial A/B Testing: Two representative users tested both Design A and B prototypes in a counterbalanced order.
  2. Refined Prototype Testing: Three users tested the refined prototype, focusing on specific user flows.

Evaluation Tasks

For the refined prototype, I developed three core tasks to evaluate different aspects of the application:

  1. Music Discovery and Playback: Find and explore music by a specific artist, navigate to an album, select a song, adjust playback settings, and add to a playlist.
  2. Plugin Management and Customization: Find a specific visualization plugin in the marketplace, view its details, install it, and configure its settings.
  3. Music Organization and Tagging: Create a new tag, find songs in a specific genre, apply the tag to multiple songs, and create a smart playlist based on the tag.

Key Findings

Strengths:

  • Users appreciated the collapsible navigation bar that allowed them to choose between space efficiency and clarity
  • The customizable view options for music browsing were well-received
  • The visual feedback for actions throughout the interface enhanced the feeling of control
  • The core modularity concept resonated strongly with users

Areas for Improvement:

  • Plugin compatibility indicators were unclear, creating uncertainty during selection
  • The multi-step tagging process felt unnecessarily complex
  • Users experienced inconsistent behavior when switching between different view modes
  • Advanced audio settings were buried too deep in the menu structure

Severity Rating System

I used a 4-point severity scale to prioritize the identified issues:

  1. Critical (4): Prevents task completion; requires immediate resolution
  2. Serious (3): Significantly hinders performance; high priority fix
  3. Moderate (2): Creates confusion or inefficiency; should be addressed
  4. Minor (1): Slight annoyance but doesn't impede task completion; low priority

This helped me focus on the most important improvements for the next iteration.

Refined Design Direction

Based on the evaluation findings, I developed a set of recommendations for the final design:

  1. Search & Discovery Improvements

    • Redesign search results to prioritize by relevance first, then offer category filtering
    • Implement contextual long-press menus for quick actions on songs and albums
    • Restructure playback settings to bring frequently used controls to the first level

  2. Plugin System Refinements

    • Create a more prominent access point to the plugin marketplace
    • Redesign plugin details page with clear compatibility indicators
    • Add visual progress indicators during installation
    • Group plugin settings into collapsible categories to reduce visual complexity

  3. Organization System Optimization

    • Make tag creation more discoverable with a persistent "+" button
    • Redesign the multi-select interface with clearer affordances
    • Simplify smart playlist creation with visual rule building
    • Add consistent save behavior throughout organization interfaces

I also crafted refined user stories to guide future development:

  1. As a music listener, I want search results organized by relevance with quick filters so I can efficiently find exactly what I'm looking for.
  2. As a power user, I want contextual menus available through gestures like long-press so I can quickly perform common actions.
  3. As a plugin explorer, I want clear visual feedback during the installation process so I know exactly when a plugin is ready to use.
  4. As an organization-focused user, I want intuitive batch operations for tagging so I can efficiently organize large music collections.
  5. As a playlist creator, I want a visual rule builder for smart playlists so I can easily create complex content filters.

Conclusion and Next Steps

The ModuMuse project demonstrates how a user-centered design approach can transform a complex problem space into an intuitive, powerful solution. Throughout this semester-long journey, I:

  • Researched user needs in the audio management space, identifying key pain points and opportunities
  • Designed multiple concepts that approached the problem from different angles
  • Prototyped increasingly refined interactions that balanced power and simplicity
  • Evaluated these prototypes with representative users to validate and improve my designs

While the current prototype is not yet ready for development, it provides a solid foundation for creating a truly user-centered music management application. The next steps would include:

  1. Implementing the recommended refinements based on usability testing
  2. Creating a functional prototype to test real data interactions
  3. Developing technical specifications for the plugin architecture
  4. Exploring monetization strategies for the plugin ecosystem

This project has deepened my understanding of user-centered design principles and strengthened my UX research and design skills. I look forward to applying these learnings to future projects and continuing to develop solutions that genuinely meet user needs.
